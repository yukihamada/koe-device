## 1. 不可逆コスト順序ゲート（v3 の「宣言」を実行可能な関門に置換）

**原則: 後戻りできないコスト（PCB発注/eFuse焼き/認証NRE/在庫）を負う前に、後戻りできるコスト（コード/実測/$0検証）で仮説を潰す。** 各ゲートは git artifact で閉じる。

### G0 — ハードを作らない（$0・需要の所在を実測）【最優先・ここを飛ばすと全てが砂上】
PWA `mcp.koe.live/takibi`（本番稼働中）+ **市販 BLE ボタン**（M5 Dial / Shelly Button / Flic ¥500-2000）で「物理トリガー→薪に週何回触れ、N日後も残るか」を実測。
- **通過条件（不可逆コミット）**: 1セグメント（JiuFlow 道場を第一）で、設置 N 台が **週次タッチ ≥ X 回 / 30日残存 ≥ Y%** を満たす実データ。Amazon Dash 墓場リスクをスライドでなく数値で否定。
- **並行**: WhatsApp/Telegram bot → 焚き火、USSD/SMS → 薪 を立ち上げ、非スマホ層（アフリカ/インドネシア）への到達を $0 で測る。**物理デバイスより桁違いに広く届く可能性**を先に評価。
- **これが緑になるまで自社 PCB を発注しない**（不可逆コミット）。

### G1 — 既存資産だけで E2E green（ハード不可逆コスト0・コードのみ）
XIAO ESP32-S3 Sense（$13.99・技適/FCC/CE/IC 取得済モジュール）1台 + 既存サーバ + 新規 `takibi.rs`。**ハードは買うだけ、不可逆コストなし。** 必要な実コミット（順序固定）:

1. **`firmware/src/takibi.rs` 新規作成** + `main.rs` の SOLUNA UDP 経路（L50-166）を `archive/soluna/` へ物理 move（削除でなく退避）。`main.rs` 冒頭 doc comment（L6-10 の `Mic→ADPCM→UDP 239.42.42.1:4242`）も書き換え。製品の自己説明がインカムのままなのは最悪の不整合。
   - 動作: `[長押し] → I2S録音(16kHz mono) → Opus 8-16kbps → HTTPS multipart POST /api/takibi/log` → **即時LED緑+触覚（STT待たない＝two-stage 1段目）** → 応答で薪ID/転写受領 → LED確定（2段目）。`[受信] → GET /api/takibi/inbox(SSE/poll) → voice_ready の mp3 → DAC再生`（"聴く"は能動操作=別タップ）。
2. **`server/src/main.rs` に 2エンドポイント追加**（既存 `handle_transcribe` L374/L1091 と `handle_ai_proxy` L377 を内部で呼ぶだけ）:
   - `POST /api/takibi/log`: device-token(Bearer) + multipart(audio + idempotency-key=`device_id+seq` + lang) → transcribe(Groq Whisper) → atsm.wtf 薪投稿中継 → レート制限/冪等 → `200 {maki_id, transcript}`。
   - `GET /api/takibi/inbox?since=<cursor>`: device-token / SSE or poll → 新着薪メタ + `voice_ready`。**クローン声生成は非同期ジョブ**（voice-clone を裏で叩き完成後 `voice_ready=true`+mp3 URL を push。同期だと再生まで数秒〜十数秒で UX が死ぬ）。
   - 読取（公開薪一覧）と書込（log/speak=token必須）を分離。CORS:* は読取のみ。
3. **`ota.rs` に ed25519 署名検証**（L64 `esp_ota_end` の前に `esp_image_verify`、公開鍵をファーム埋め込み、ロールバック保護）。**ハードコスト0・今日着手可能・最高ROI**。
4. **`network.rs` の `env!("KOE_WIFI_SSID/PASS")`(L21-22) 撤廃** → NVS暗号化保存 + BLE Improv-WiFi / SoftAP captive portal を最小 fallback。（Matter/NFC は G2）。
5. **`power.rs`**: L36 `light_sleep_enable: false`→`true`（全モード）、`sdkconfig.defaults` に `CONFIG_FREERTOS_USE_TICKLESS_IDLE=y` 追加（`CONFIG_PM_ENABLE=y` は既存）、`DeviceMode::load()`(L20-25) の NVS 読込 TODO 実装。
6. **オフラインキュー**: WiFi/STT 不達 → NVS/PSRAM に冪等(`device_id+seq`)キュー → 再接続で flush。圏外で押しても触覚+光で「声は預かった」を即提示（**スマホに対する数少ない実優位**）。
- **通過条件（green の定義）**:
  1. XIAO 実機1台で「長押し→喋る→atsm.wtf に薪→クローン声が鳴る」が通る（**動画1本**）。
  2. レイテンシ実測を秒で出す（録音終了→触覚 P95、クローン声再生 P95）。**悪い回線**（`tc/netem` で高遅延・パケロス・帯域制限を再現＝ブラジル4G輻輳/インドネシア captive portal 相当）でも計測。
  3. 圏外→復帰で薪が二重投稿されない（冪等確認）。

## 2. ハードの存在理由（v3 の自己矛盾を解消・1点賭けを検証可能に）

> **「拠点の一角に置きっぱなしで、スマホを取り出さず・アプリを開かず・誰でも、声を焚き火に残せる共有の常設端末」**

PWA が本番稼働している以上、物理デバイスの増分価値は **「常設・共有・置きっぱなし・誰でも」の物理プレゼンス1点**に賭ける。**この仮説は §1 G0 で $0 検証してから不可逆コストを負う**（v3 はここを検証せず本線化していた）。

却下した対立価値（理由を残す）:
- ❌ 真のハンズフリー(運転中) → ウェイクワード常時マイクは mic キル方針と矛盾。上位機の任意機能に降格。
- ❌ モバイル携帯 PTT → スマホが電池/レイテンシ/画面で上回る。作らない。
- ✅ 常設・共有・スマホ不要 → スマホは「個人の・しまう」もの。共有常設端末はスマホの構造的死角。

### 2.1 主販路 = B2B 空間什器（「Amazon Dash の墓場」への回答）
- **コンシューマ単品ボタン売りは捨てる**（返品/サポート/単機能ボタンの墓場）。
- 道場/カフェ/宿/コミュニティ拠点に置く木・石・和紙の常設オブジェ + 月額（声ネットワーク利用料）。
- 既存 B2B 網（JiuFlow 道場 / bim.house 工務店 / MU 拠点）と相乗。**設置先は電源・WiFi が保証される** → §4 で電源/プロビジョニング制約が劇的に緩む。
- **G0 のリテンション実測は JiuFlow 道場1セグメントに絞る**（道場/カフェ/宿を並べない。1セグメントで LTV/CAC を実数で出す＝§9）。

### 2.2 並行ソフト到達（北極星「世界中で使われる」への最短距離）
非スマホ層（アフリカ/インドネシア）には WhatsApp/Telegram bot → 焚き火、USSD/SMS → 薪 が物理デバイスより桁違いに広く・安く届く。**ハード投資の前にこのソフト到達で需要の所在を特定**（§11 の △ を G0 並行施策に格上げ）。

### Matter（屋外/家庭SKU のみ採用）
屋外/家庭設置の電池SKUに **Matter コミッショニング(QR)** を載せ、WiFi プロビジョニング地獄を回避（HomeKit/Google Home/SmartThings の普及インフラ）。**什器SKUは事業者が設置時に WiFi 設定する（B2B事前設定）ので Matter 不要**＝ESP-Matter SDK 統合コスト($)を屋外SKUに限定。
- トレードオフ: クラウド STT 前提なので結局 IP ゲートウェイ(WiFi/Thread BR)が要る。が「電源を入れたら繋がる」に最も近い。

却下:
- ❌ nRF5340/nRF54L15（`manufacturing/gerbers/koe-coin*` 実在）: **ネット不可・SOLUNA/UWB インカム遺産**。`archive/` へ退避。製品の核（クラウド STT）を物理的に実行できない。
- ❌ DW3000/DW3720(UWB)（`koe-pro`/`koe-hub` 実在）: 測距用途。本製品と無関係。`archive/` へ。
- △ LTE(Blues Notecard グローバル eSIM): WiFi 設定摩擦を完全に消すが原価+$15+月額・各国バンド/eSIM 認証地獄。**屋外/僻地 SKU 専用に PMF 後保留**。

- △ LoRa/Meshtastic: 僻地 WiFi 不在でテキスト薪を先に飛ばし音声後追い。**僻地SKU 将来**。

## 4. 電源設計 — SKU で割って重量級ゲートを分離

### 4.0 SKU 別電源方針（v4 の核心的単純化）
| SKU | 電源 | 電池 | 安全ゲート | 設計複雑度 |
|---|---|---|---|---|
| **基本(什器)** | USB-C 常時給電 + **スーパーキャパ瞬断保持**(数秒) | **電池レス** | **IEC62133/UN38.3/EU電池規則を回避** | 最小（PMIC/燃料計/ソーラー不要） |
| **屋外** | ソーラーMPPT + LiFePO4 | LiFePO4 1.5-2Ah | UN38.3/IEC62133-2/EU電池規則 全対応 | 最大（§4.1-4.4） |

> **what this buys**: 主販路の什器SKUから電池を外すと、最重量級の安全/輸送/EU電池規則ゲートを**丸ごと回避**でき量産が一気に現実化。10h/ソーラーは「屋外SKUの差別化要件」に隔離（要件は屋外SKUで死守）。什器SKUの「10h駆動」は**電源喪失時のスーパーキャパ瞬断保持＋オフラインキュー保持**として満たす（バックアップ要件に降格）。

### 4.1 PMIC 一本化（屋外SKU・現 BOM の致命を解決）
現 `BOM.csv` 実体: MCP73831(power-path無・満充電付近で負荷電流が充電判定を乱す) + AP2112K LDO(効率45-65%) + 800mAh 素LiPo。NTC/保護IC/UN38.3 無 → IEC62133-2 で出荷不可。
- **決定: 単一 PMIC**。第一候補 = **TI BQ25895**（power-path + I2C 燃料計内蔵・ESP32 と組む実績/ドライバ資産が厚い）。nPM1300(Nordic) を代替に保持するが、**Nordic SoC 前提の最適化で ESP32-C6 と組むと I2C ドライバ自前実装の負担が大きい**ため第一候補から降格（v3 の nPM1300 第一を再検討）。
- ソーラー(MPPT)+USB の true power-path、電池保護(過充/過放/過電流)+NTC、燃料計、ボタン管理を1チップに集約。**MCP73831 は物理削除。**
- ⚠ レジスタマップで確定すること: I2C 実ドライバ・NTC β値・充電窓レジスタ・VBUS/VSYS 優先度・ship mode 起床シーケンス・ESP32 リセット/起床 GPIO ↔ PMIC 論理。誤ると起動しない個体が出て歩留り直撃。

### 4.2 昇降圧化（屋外SKU）
**AP2112K LDO → `TPS63802` buck-boost**（LiFePO4 全域で効率 88-92%、実駆動 1.3-1.5倍）。
- TX バースト(瞬時400-500mA)対策: PMIC 出力に**バルクコンデンサ**。容量は「TX バースト電流 × 許容ドループ」から逆算（220-470µF は上限、実数は §1 実機の突入波形で確定）。ソフトスタート突入 + インダクタ電流リミット超過は起動失敗の原因。
- インダクタ: 飽和電流 > ピーク(0.5-0.7A)・低 DCR・EMI 配慮。入出力コンデンサは DC-bias derating を部品表化。

### 4.3 ソーラー / 室内光（屋外SKU・採否を数値で確定）
- **屋外/明窓SKU**: 6V 1-2W パネル → PMIC(MPPT) → 1S LiFePO4。日中 パネル出力>平均消費 で充電しながら連続運用。
- **室内光ハーベスタ(AEM10941/BQ25570) 全振りは却下**: 室内光は μW級で、録音+WiFi/Opus TX のバースト電力(数百mW・数秒)を賄えない。ハイブリッド（ハーベスタ=待機保持/USB・ソーラー=実使用充電）が現実解。
- **ソーラーは全SKU必須から外す**（§4.0）。屋外SKUで死守、什器SKUは USB-C 常時給電。

### 4.4 電池と安全（屋外SKU）
- **第一候補 = LiFePO4 1.5-2Ah**（高温安全・サイクル長・屋外/寒冷地・UN38.3/IEC62133 ゲートに対し発火リスクを構造的に低減）。電圧域(3.0-3.6V)は TPS63802 で吸収。
- **寒冷地(北欧)屋外SKU は LTO(チタン酸リチウム)も評価**: 0℃以下充電耐性・2万サイクル。原価/密度で不利だが什器=常時給電なら密度は非問題、e-waste/修理可能性で最強（別案として保持）。
- 充電温度窓 0-45℃ を **ハード(PMIC NTC)で強制**（ファームでなく）。北欧は寒冷地で 0℃以下充電→Li 析出→内部短絡→発火が実リスク。NTC β値/充電窓レジスタ/SHPHLD 論理を回路図とレジスタマップに落とす。
- 燃料計標準化（残量を LED/クローン声で通知）。輸送 **UN38.3** 出荷前取得（空輸必須）。

### 4.5 電源収支（**全行 unverified・§1 G1 実機 INA226 で置換するまで仕様/LP/BOM に書かない**）
| 状態 | 想定(屋外C6/TWT) | 備考 |
|---|---|---|
| Deep idle(TWT/Thread 受信待ち) | 1-5mA | C6 TWT で一桁削減狙い |
| WiFi/Thread 維持(light sleep+DTIM) | 15-30mA | light_sleep 有効化が前提(§1.5) |
| 録音+STTアップ(バースト) | 120-180mA | 数秒 |
| クローン声再生 | 80-150mA | 数秒〜十数秒 |

加重平均(常設・たまに使う)目標 **平均 10-20mA** → 1500mAh LiFePO4 で **75-150h** が机上値。**「約10h」は屋外SKUの最低保証ライン**（無日照・ヘビー利用でも満たす設計余裕）。什器SKUは常時給電で「10h」は瞬断保持要件。
> ⚠ INA226 実測で置換するまで、曇天・木陰・夕方の**最悪ケース日照**で「充電 − 平均消費 > 0」を実証するまで、「10h(実測)」「ソーラー連続運用(実証)」は禁止語（§9）。

## 6. ファーム

### 6.1 takibi.rs — §1 G1 参照（製品の存在理由・最優先・現状コードに不在）

### 6.2 レイテンシ予算（机上→実測で埋める）
押下→録音→HTTPS multipart→Groq Whisper→atsm 投稿→inbox→voice-clone→DAC 再生は数秒〜十数秒になりうる。「喋ったのに無反応の数秒」は致命。
- **two-stage feedback**: ①録音終了→**触覚+LED 確定 P95 < 800ms（目標値・STT 待たずローカル確定）**。②薪反映・転写は後追い。
- **クローン声再生開始 P95 < 4s（目標値）**。サーバ側で TTS を**非同期ジョブ + 事前生成キャッシュ + ストリーミング再生**で隠す。
- **§1 G1 実機 + `tc/netem` 悪回線で P50/P95 を実測**してから仕様化。4s を超えるなら「聴く」を**完全非同期(プッシュ通知的)に倒す**判断を先に確定（レイテンシ要件を消し、TTS をバッチ化して従量原価も下げる）。
- **受信(聴く)は能動操作に分離**（常時 inbox 自動再生はスパム/騒音化）。

### 6.3 オフライン耐性（スマホに対する実優位・現状は UDP マルチキャストで公衆網即死）
WiFi/STT 不達 → NVS/PSRAM 冪等(`device_id+seq`)キュー → 再接続で flush。**UX**: 圏外で押しても触覚+光で「声は預かった」を即提示、復帰時に静かに送る。Opus 8-16kbps 固定 + 指数バックオフ + captive portal 検知(新興国公衆WiFi)。「1薪 = 何KB」表示(従量データ地域の信頼)。

### 6.4 プロビジョニング（SKU別・「スマホ不要」自己矛盾を解消）
`network.rs` の `env!`(L21-22) **撤廃**。優先順位:
1. **B2B 事前設定**（什器SKU の正規フロー）— 事業者が設置時に拠点 WiFi 設定＝エンドユーザーのスマホ介在ゼロ。
2. **Matter コミッショニング(QR)** — 屋外/家庭SKU で既設ハブがあれば最良。
3. **NFC タップ設定** — 設定済みカード/スマホをかざす。
4. **BLE Improv-WiFi / SoftAP captive portal** — fallback（G1 で最初に実装）。
- 設定は **NVS 暗号化保存**。デバイス毎 provisioning token を初回発行(§7)。

### 6.5 省電力（現コード実態に整合・要修正）
- 確認済: `power.rs::set_cpu_80mhz` は `esp_pm_configure` を実呼出(L39)。ただし L36 `light_sleep_enable: false` → light sleep 無効。**全モードで `true`** + `CONFIG_PM_ENABLE`(既存) + **`CONFIG_FREERTOS_USE_TICKLESS_IDLE`(`sdkconfig.defaults` に追加必須)** + DTIM/TWT 有効化。
- `DeviceMode::load()`(L20-25) の NVS 読込 TODO 実装（再ビルド無しでモード切替）。
- 10h は INA226 実測ログ(平均mA×容量)で証明するまで「未確認」明記。

### 6.6 アンテナ DFM
PCB アンテナ直下に GND/銅/部品/電池/磁石を置かない keepout を**意匠(和紙/木/石)決定と同時に固定**。磁気マウントはアンテナ非干渉位置に 3D 確定（フェライトでも利得を数dB食う）。**量産前に VNA で S11 < -10dB @2.4-2.48GHz 実測**。深圳ラボで EMI プリスキャン(伝導/輻射)を書類提出前に実施。OTA 成功率はここで決まる。

## 7. セキュリティ・本人性・プライバシー

### 7.1 OTA 署名（現 ota.rs L60-64 の致命・§1 G1 で即着手＝最高ROI）
現状 `esp_ota_write`→`esp_ota_end` のみ＝署名検証ゼロ。OSS でバイナリ世界公開する以上、サーバ侵害/MITM で全端末に任意ファーム＝ボットネット化。**EU CRA・RED Art.3.3(d/e/f) 抵触で CE マーキング不可＝EU 出荷ブロック。**
- **ed25519 署名 → `esp_image_verify` を `esp_ota_end` の前に検証**。ロールバック保護。**ハード不可逆コスト0・今日着手可能。**
- eFuse で **Secure Boot v2(RSA-3072) + Flash Encryption**（量産フロー決定後）。
- ⚠ 量産前先決: eFuse は不可逆（焼いたら戻せない・デバッグ不能・失敗品廃棄）。Release key 管理(HSM)・per-device vs shared key・産線 eFuse 焼き治具・焼き失敗品の扱い。

### 7.2 焚き火なりすまし/スパム
`/api/takibi/*` 書込 = デバイス token + 署名 + レート制限。読取(公開)と分離。CORS:* は読取のみ。

### 7.3 共有端末の「誰の声か」同意（GDPR/LGPD/POPIA・実装に落とす）
リビング/道場の共有端末は「誰の同意済みの声か」の特定が困難。
- **物理トークン(NFC 木札/コイン)で本人性を物理化**: 木札をかざす→「その人として薪をくべる」。**クローン声生成は本人木札タップを必須**にする最小同意ゲートを、サーバ側 device-token と一緒に**エンドポイントで実装**（文書でなく）。
- 木札の発行/紐付け/失効フロー + 紐付け前の匿名薪の扱いを定義。
- 録音前の物理 mic-kill(MIC_3V3 直遮断 + LED2 直点灯)を trust anchor として維持。
- GDPR/LGPD/POPIA: 音声の保持期間/保管リージョン/削除 API を**エンドポイントで用意**。EU 向けは **EU リージョン処理**(koe-mcp Fly 多リージョン)。北欧データ保護当局(IMY/Datatilsynet)は共有端末での非同意者の声取得を厳しく見る。

## 10. クラフト・UX（世界品質・所作まで）

- **「機能」でなく「所作」へ**: WS2812×3 + 振動は機能。物理オブジェクトを**ランタン/石/和紙のいずれか1つに決め**、押す場所が指に分かる触覚アフォーダンス、点灯が他者にそっと伝わる**呼吸する縁/周辺光**(拡散面 + PWM ガンマ + sub-LSB ディザ)まで設計図に。色だけに依存しない(色覚多様性)。
- **所作のタイムラインを ms 単位で図面化し動画で合否判定**（受け入れ基準 §1 は機能チェックでなく体験基準も含む）: 例「長押し→0.3秒以内に縁が一拍だけ呼吸し、指を離すと光が静かに落ちて消える」。LED ガンマ/触覚波形/無音の質まで。Apple/無印/teenage engineering 水準＝「動く」でなく「触れたくなる」。
- **NFC 木札を「開封の儀式」「所作」と統合**: 木札をかざす=焚き火に名乗る。手触り・素材・音・光まで設計（機能要件の箇条書きで終えない）。
- **開封の3秒**: 再生紙・組立不要 + 文字ゼロのピクト + 触覚で初回儀式完結（多文化/識字率配慮）。押す場所が光って誘う→最初の薪を自分の声で残す。
- 操作は **押す/離す/長押しの3つ**で全機能完結。STT 対応 ja/en/pt-BR/id/sw/fr/ar、コードスイッチ対応。**Groq Whisper の sw(スワヒリ)/id/アラビア語方言の実精度を実音声で計測**（低精度言語は「喋ったのに違う薪」で信頼を一度で失う）。
- ボタンは**シリコンキー**(濡れ手/手袋可)。多言語 LP + 多通貨 Stripe + 地域別電源は USB-C PD 共通。文化非依存（和紙/石が刺さらない地域あり→触覚+色覚非依存+文字ゼロで担保）。

## 11. 採用しなかった主な別案（理由を残す）

- ❌ **熱電(TEG)で焚き火の熱から発電**: 物語最強だが実焚き火必須で常設用途と矛盾・効率/安全/原価が非現実的。ブランド資産の年1 PR什器/限定アート1点のみ。製品電源としては検討対象外で確定。
- ❌ **室内光ハーベスタ全振り(電池レス)**: μW級で録音+TX バーストを賄えない(§4.3 数値根拠)。ハイブリッドで採用。電池レスは間欠PTT+e-ink の別フォーム将来案（録音ローカルキュー→1日1回TX・e-ink電力ゼロ保持なら μW でも成立しうる＝北欧サステナ訴求最強）。
- ❌ **常時ウェイクワード**: mic キル方針・電力と矛盾。上位機の任意機能に降格。
- ❌ **nRF5340/nRF54L15 + 外付け Border Router**: ネット不可・UWB/インカム遺産。Matter/Thread の利点は C6 で取れ、ESP32 のサプライ/OSS が厚い。`archive/` へ。
- ❌ **PTT を省き周辺マイク常時収音**: mic キル方針と衝突。NFC 木札で本人性を物理化(§7)を採用。
- △ **既存スマートスピーカー(Echo/Nest 1.5億台)へ Matter/Alexa Skill 連携**: ハード製造ゼロで「常設・共有・ハンズフリー」を即グローバル配布。**自社什器の存在理由を最も鋭く脅かす対抗案＝G0 と並行で先に潰す**。
- △ **PWA + 市販 BLE ボタン**: 資本効率最良。**G0 として不可逆コミット化**（ハード投資のゲート・§1）。
- △ **WhatsApp/Telegram bot / USSD/SMS → 薪**: 非スマホ層に物理デバイスより桁違いに広く・安く届く。**G0 並行のソフト到達として正典化**（§2.2）。
- △ **B2B 空間什器(木/石/和紙)**: 単機能ボタンの墓場回避。**主販路**(§2)。
- △ **Raspberry Pi Zero 2W ローカル Whisper**: 従量データ節約・GDPR/LGPD/POPIA データ主権(声を国外に出さない)。**EU/拠点向け上位 SKU の将来オプション**。クラウド往復ゼロは EU 最強の差別化だが、基本機はクラウド STT で足りる。
- △ **LTE(Blues Notecard グローバル eSIM)**: WiFi 摩擦を完全に消すが原価+$15+月額・各国認証地獄。屋外/僻地 SKU 専用に PMF 後保留。
- △ **LoRa/Meshtastic トランスポート**: 僻地 WiFi 不在でテキスト薪を先に飛ばし音声後追い。僻地 SKU 将来。LAN メッシュ+クラウド同期ハイブリッドも一案だが基本は HTTPS ユニキャストで足りる。
- △ **LTO(チタン酸リチウム)電池**: 北欧寒冷地屋外SKUで 0℃以下充電耐性・2万サイクル。原価/密度不利だが什器=常時給電なら密度非問題・修理可能性最強（屋外SKUの寒冷地版で評価）。
- △ **EU を第一認証市場にする逆張り**: 什器SKU=電池レスで EU 電池規則を回避できるなら「最重量級を先に通せば他は楽」。第一市場は G0 実需データで確定。

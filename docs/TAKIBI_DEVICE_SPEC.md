# 焚き火デバイス — 製品仕様（声で焚き火に薪をくべる声デバイス）

> 状態: ドラフト（意思決定の正典化）。実発注は人間承認後。
> 関連: PWA = `mcp.koe.live/takibi`（声で薪をくべる/聴く・予約受付）/ ファーム = この repo `firmware/`

## 1. 製品定義

手のひらサイズの**声デバイス**。ボタンを押して話すと、声がクラウドで文字起こしされて
ATSM の焚き火（atsm.wtf）に薪としてくべられ、みんなの薪を本人クローン声で聴ける。

- **押して話す → くべる**: 録音 → `mcp.koe.live /api/takibi/log`（STT→atsm_log）
- **聴く / 焚き火ラジオ**: 薪を `/api/takibi/speak`（クローン声TTS・mp3キャッシュ）で再生・新着自動読み上げ
- 体験の先行版は PWA で本番稼働中（ホーム追加でアプリ化）。物理デバイスはその「常設・ハンズフリー・スマホ不要」版

## 2. プラットフォーム決定: **ESP32-S3**

| 候補 | 判定 | 理由 |
|---|---|---|
| **ESP32-S3** | ✅ 採用 | WiFi内蔵で単体ネット到達・既存ファーム資産・安価($2-3級モジュール)・低消費の余地 |
| nRF5340 | ✕ 非採用 | **WiFi/セルラー無し**＝単体でネットに出られず、必ずスマホゲートウェイ前提。声デバイスの中核(クラウド往復)に不適。LE Audioプレミアム声イヤホン等の別ラインなら可 |
| ESP32-C6 | △ 省電力版候補 | WiFi6+BLE+Thread・単核RISC-V。計算はクラウド任せなのでC6で足りる場面あり |

接続方式は2系統で展開:
- **WiFi版**: 自宅・拠点向け。最安。WiFiプロビジョニング(BLE/SoftAP)が必要
- **どこでもLTE版**: 屋外・設定不要。`ESP32-S3 + LTE-M`（Walter / Blues Notecard / nRF9160 等）。+部材費・データ

## 3. 電力設計: 目標 **約10時間駆動**

焚き火デバイスは常時ストリーミングではなく「待機 → 押して話す → 数秒送受信」のデューティ。

| 状態 | 概算電流 |
|---|---|
| WiFi送受信(アクティブ) | ~120-160mA |
| WiFiモデムスリープ(CPU稼働) | ~20-40mA |
| ライトスリープ | ~2-3mA |

- 待機をライトスリープ＋モデムスリープにすれば**平均20-30mA** → 10hに必要なのは**約300mAh**
- **800-1000mAh の単セルLiPo で 10h＋十分な余裕**（最悪・常時WiFi受信でも ~1200mAh で到達）
- ⚠ **前提となる省電力パスが現ファームで未稼働**（10h達成の致命点・要修正）:
  - `firmware/src/power.rs::set_cpu_80mhz()` … `esp_pm_configure` を**呼んでおらず80MHz化が効いていない**
  - `firmware/src/power.rs::enable_modem_sleep()` … 定義のみで `main.rs` から**未呼出**
  - `DeviceMode::load()` … NVS読込がTODO（モードが再ビルドでしか変えられない）

※数値はエンジニアリング概算（実機実測で要確定・未確認）。

## 4. ソーラー充電（屋外前提）

- **小型パネル 5-6V / 1-2W**（約60-110cm²）で good sun時 ~150-350mA
- 平均消費0.1-0.15Wに対しパネル1-2Wなら、**屋外日中は駆動しながら充電 → 実質連続運用**。10hは無日照時の予備
- 充電IC: 単セルLiPoなら **CN3791（MPPT・ソーラー最適）** か SPV1040。簡易なら TP4056＋ダイオード
- 線引き: **屋外は実用／屋内ソーラーは弱い → USB-C充電前提**

## 5. 形状

ソーラーには上面の受光面積が要る → コイン/ペンダントは小さすぎ。
**パック/ランタン型**（この repo の `stone/` 筐体・Lantern STAGE）の上面にパネルが自然。
